# KIXO

Премиальный sneaker-магазин для Узбекистана. Next.js App Router, TypeScript,
PostgreSQL, Prisma, Auth.js / NextAuth, Tailwind CSS 4, shadcn-style Radix Button,
Motion, React Hook Form, Zod, TanStack Query, Sonner.

Это рабочий **демонстрационный магазин**, а не открытый для реальных продаж сервис.
Каталог и заказы сохраняются в PostgreSQL. Seed содержит 24 демо-товара и 207
варианта. Фотографии иллюстративные: они не показывают точные модели из карточек.
Реальные заказы не отправляются курьеру; отзывы покупателей не выдумываются.

## Быстрый запуск

Нужны Node.js 22.12+ (проверено на 26), npm, Docker Compose или PostgreSQL 17+.

```bash
npm ci
cp -n .env.example .env
# Укажите NEXTAUTH_SECRET (openssl rand -base64 32), пароль администратора,
# строку DATABASE_URL и адрес магазина.
docker compose up -d db
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

Откройте http://localhost:3000 . Если порт занят, выберите другой и **одинаково**
измените `NEXTAUTH_URL`, `NEXT_PUBLIC_SITE_URL` и адреса в `playwright.config.ts`:

```bash
npm run dev -- --port 3001
```

В текущей рабочей среде `.env` подключён к PostgreSQL проекта Supabase через
Session pooler на порту 5432 с обязательным TLS. Пароль закодирован в connection
string и хранится только в игнорируемом `.env` с правами `600`. Прежняя локальная
база `/tmp/kixo-pg` больше не используется приложением.

Проверка подключения без вывода секретов:

```bash
npm run db:check
```

При использовании текущего Supabase-подключения запускать Docker не требуется.
Для перехода на локальную БД возьмите локальный `DATABASE_URL` из `.env.example`,
запустите Compose и примените миграции/seed. Тесты с записью запускайте в отдельной
тестовой БД; рабочее облачное подключение не нужно использовать для E2E fixtures.

## Что работает

- Главная: hero, популярные пары, бренды, коллекция, новинки, trending,
  lifestyle, подписка и информационные страницы.
- Каталог из PostgreSQL: поиск по модели/бренду; бренд, цена, EU-размер, цвет,
  пол, наличие; сортировка и «Показать ещё». Состояние хранится в URL.
- Товар: галерея, увеличение с клавиатурным управлением, выбор размера/цвета,
  количества, остатки, рекомендации. Недоступные размеры заблокированы.
- Корзина и избранное сохраняются в браузере, синхронизируются между вкладками.
  Авторизованное избранное также записывается в БД и видно в кабинете.
- Корзина получает актуальные цены и наличие с сервера. `FIRST10` — демо-промокод
  на 10% от 500 000 UZS. Доставка 30 000 UZS, бесплатно от 1 500 000 UZS **после скидки**.
- Гостевой и авторизованный checkout. Сервер пересчитывает сумму, объединяет
  одинаковые варианты и атомарно списывает остатки. Уникальный ключ запроса
  предотвращает повторные заказы; Serializable-транзакции повторяются при конфликте.
- Регистрация, вход, выход, профиль, адреса, история заказов и статусов.
- Гостевой заказ доступен по HttpOnly cookie в том же браузере 30 дней.
  Покупатель видит только свои заказы; администратор — все. Токен не передаётся в URL.
- `/admin`: показатели, график за 7 дней, оплаченная выручка, популярные товары;
  создание/редактирование/архивирование товаров, переводы EN/UZ, цены,
  SKU/цвета/размеры/остатки; изображения, бренды и категории; заказы,
  фильтры, история статусов; промокоды, заголовок и изображения баннеров, контакты.
- Русский, узбекский и английский интерфейс витрины, покупки, кабинета и справки;
  переводы описаний товаров — в `ProductTranslation`. Административный интерфейс — русский.
- SSR, metadata/Open Graph, Product JSON-LD, sitemap и robots, локальный Inter,
  `next/image`, lazy loading, reduced motion, мобильная вёрстка от 320px.

## Администратор

Перед seed задайте `SEED_ADMIN_EMAIL` и сильный `SEED_ADMIN_PASSWORD` в `.env`.
Seed создаёт администратора только при отсутствии пользователя с таким email и
**не повышает роль уже зарегистрированного покупателя**. Пароль существующего
администратора повторный seed не меняет. Локальный сгенерированный пароль
находится только в игнорируемом `.env` — универсального публичного пароля нет.

Войдите через `/login`, затем откройте `/admin`. Роль повторно считывается из БД
при каждом административном запросе; клиент не может назначить себе роль.

Статусы: `NEW → CONFIRMED → SHIPPED → DELIVERED`. Отмена возможна до отправки.
При отмене остатки возвращаются один раз. Доставка наличного заказа переводит
его платёж в `PAID`; в выручку входят только оплаченные платежи.
После доставки/отмены переходы статусов заблокированы. Возвраты уже доставленных
заказов пока обрабатываются оператором отдельно; интерфейс автоматического возврата
денег не реализован.

## Внешние подключения

**Click и Payme:** намеренно отключены и недоступны для выбора. Сервер отклоняет
онлайн-оплату и никогда не сообщает об успешном платеже. Чтобы включить их, нужны
merchant credentials и отдельные проверенные адаптеры официальных API: создание
платежа, проверка подписи/auth вебхука, идемпотентность `Payment.externalId`, сверка
суммы/валюты, переходы `PENDING/PAID/FAILED/REFUNDED`, sandbox и provider contract
tests. Обработчики вебхуков пока не установлены. Наличие ключей само по себе не
включает онлайн-оплату. Наличный checkout полностью работает.

**S3-compatible storage:** реализованы admin-only presigned PUT, лимит 5 MiB,
JPEG/PNG/WebP, проверка метаданных объекта после загрузки и сохранение URL в БД.
Заполните `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`,
`S3_SECRET_ACCESS_KEY`, `S3_PUBLIC_URL`. Нужны разрешения PutObject/HeadObject,
CORS PUT с домена магазина и публичная выдача изображений через HTTPS/CDN.
Перезапустите Next после изменения хоста: он добавляется в `images.remotePatterns`.
Без S3 можно использовать файлы из `public/images/` и URL Unsplash.
Удаление изображения из карточки удаляет запись в БД; очистка объектов S3 остаётся
за политикой хранения бакета. Последнее изображение удалить нельзя.
S3 не проверялся на реальном бакете: реквизиты не предоставлены.

**Подписка:** email реально сохраняется в `Subscriber`. Автоматическая рассылка,
SMS, уведомления менеджеру и подключение курьерской службы пока отсутствуют.

**Supabase:** подключена PostgreSQL через Prisma и Session pooler (5432).
`DATABASE_URL` включает `sslmode=require`, `connection_limit=3`, `pool_timeout=30`
и `connect_timeout=15`. Для миграций используйте этот session pooler или прямое
подключение; порт transaction pooler 6543 для текущей настройки не нужен.
Интерактивные транзакции сервера допускают ожидание до 10 секунд и выполнение
до 20 секунд, чтобы учитывать задержку до облачной базы.

Миграция `server_only_access` включает RLS и отзывает права `anon`, `authenticated`
и `PUBLIC` на таблицы KIXO, включая историю миграций. Публичных RLS-политик нет:
все операции проходят через Next.js, который проверяет сессию и роль. Служебные
схемы Supabase `auth`, `storage`, `realtime`, `vault` не изменяются. Вход продолжает
обрабатывать Auth.js, а его пользователи хранятся в таблице KIXO `public.User`.
Supabase Auth и Storage не требуются для текущего подключения базы. Не помещайте
connection string или пароль в переменные `NEXT_PUBLIC_*`.

## Production и проверки

Подробный runbook: [docs/PRODUCTION.md](docs/PRODUCTION.md).
Контракты HTTP API: [docs/API.md](docs/API.md).
Итоговые результаты проверки: [docs/VERIFICATION.md](docs/VERIFICATION.md).

```bash
cp .env.test.example .env.test.local
# Укажите отдельную локальную TEST_DATABASE_URL с именем *_test.
docker compose -f docker-compose.test.yml up -d
npm run test:db:migrate
npm run test:db:seed
npm run lint
npm run typecheck
npm run test
npm run build
npm run test:e2e
npm run start -- --port 3001
```

Тесты отказываются использовать рабочую Supabase и запускают production standalone
на отдельном порту 3100. `.next/standalone` включает статические assets, проходит
очистку от `.env` и сканирование на секреты. Для изначально установленного браузера
можно указать `CHROMIUM_EXECUTABLE_PATH` в `.env.test.local`.

Production-шаблон настроек — `.env.production.example`; Docker runtime —
`Dockerfile` и `docker-compose.production.yml`; CI — `.github/workflows/verify.yml`.
`npm run release:check` проверяет настоящий HTTPS-домен и приватные настройки.
`npm run release:check:local` проверяет текущую локальную конфигурацию.


## Архитектура

```text
src/app/             App Router pages, SEO, route handlers
src/components/      общие компоненты, layout, UI и providers
src/features/        каталог, товар, корзина, checkout, вход
src/server/          pricing, заказы, статусы, actions, rate limiting
src/lib/             Prisma, Auth.js, валидация, browser store
src/hooks/           запрос актуальной серверной цены через TanStack Query
src/i18n/            словари RU/UZ/EN, справка, локализация товаров
src/types/           типы Prisma и сессии
prisma/              нормализованная схема, миграции, идемпотентный seed
tests/               unit/integration и Playwright E2E
```

Заказы связаны с подтверждённой суммой `expectedTotal` и хешем запроса для защиты
идемпотентности. Демо-заказы помечаются `demo=true`; их выручка не учитывается.
Деньги — целые UZS без float. `Order` хранит currency для будущего расширения;
пересчёт курсов и отображение других валют ещё не включены. `OrderItem` сохраняет
снимки имени, SKU, цены, изображения, цвета и размера. PostgreSQL дополнительно
проверяет неотрицательные остатки и согласованность итогов CHECK-ограничениями.
`Cart/CartItem` предусмотрены для будущей синхронизации авторизованной корзины;
в текущем UI источником корзины служит браузер, а сервер всегда проверяет её заново.

Чувствительные route handlers проверяют Origin и Zod; Auth.js защищает сессии и
CSRF входа, Server Actions выполняют серверную проверку пользователя/роли.
Rate limiting хранится в PostgreSQL. `TRUST_PROXY=true` включайте только за
доверенным прокси, который перезаписывает `X-Forwarded-For`; иначе лимит общий.
Устаревшие строки RateLimit рекомендуется удалять по расписанию.

Перед реальными продажами замените демо-каталог и фотографии, укажите юридические
сведения, реальные контакты/условия, настройте HTTPS, секреты, резервные копии,
мониторинг и сервисы оплаты/доставки. Фото и лицензии перечислены в
[public/images/ASSETS.md](public/images/ASSETS.md).
