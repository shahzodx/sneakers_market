## Покрытые сценарии

- Поиск и фильтры, сохранение запроса в URL, пустые состояния.
- Обязательный размер, сохранение корзины, гостевой заказ, приватность заказа.
- Серверный quote, промокод, подтверждённая сумма, HTTP 409 при изменении цены.
- Повтор запроса не создаёт второй заказ; изменённый запрос с тем же ключом отклоняется.
- Конкурентная покупка последней пары, rollback, возврат остатков при отмене.
- Наличный платёж становится оплаченным только при доставке.
- Демо-позиции не продаются в live-режиме.
- Вход администратора, создание/редактирование/архивирование товаров.
- Защита от перезаписи остатка, изменённого после открытия формы.
- Переводы, изображения по URL, профиль, адреса, ограничения роли покупателя.
- Идемпотентное избранное, реальное сохранение email подписки.
- Ограничения JSON, проверка Origin, безопасные сообщения об ошибках.
- JSON-LD/XSS-экранирование и ограничение паролей по 72 байтам bcrypt.
- RU/UZ/EN, ширины 320/768/1440px, загрузка фото и клавиатурное закрытие галереи.
- Read-only API оператора, health/readiness и security headers.

## Supabase и наполнение

Применено 5 миграций. Финальное состояние: **24 демо-товара, 207 вариантов,
1 администратор, 0 оставшихся тестовых заказов**. Описания и характеристики
подготовлены на RU/UZ/EN; добавлены цветовые варианты на пяти демо-моделях.
Фотографии иллюстративные, цены и остатки тестовые. Вручную отредактированные
описания и реальные товары seed не перезаписывает.

В public-схеме 22 таблицы с RLS; прямые права `anon` и `authenticated` отозваны.
Auth.js и серверные проверки остаются границей доступа. Служебные схемы Supabase
не менялись.

Отдельный smoke-тест production-сборки на реальной Supabase подтвердил:
каталог → quote → заказ с подтверждённой ценой → списание → вход администратора →
отмена → восстановление остатка. Временный заказ удалён адресно по уникальному
маркеру; реальные заказы/остатки не очищались.

Созданы приватные копии до и после изменений. Итоговая копия восстановлена в
пустой локальной БД: **24 товара и 207 вариантов**, ограничения схемы восстановлены.
Временные БД с копиями рабочих данных удаляются после проверки. Копии в
`artifacts/` имеют права `600` и исключены из Git/Docker/публичного артефакта.

## Аудит зависимостей

`npm audit --omit=dev`: **0 уязвимостей**.

Полный audit: **0 critical, 16 high**. Все оставшиеся high-записи образуют цепочки
одного непатченного advisory `picomatch` —
[GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf).
На дату проверки latest в registry — 4.0.7; GitHub указывает affected <=4.0.7 и
**Patched versions: None**. Поэтому предупреждение не скрывалось и не объявлялось
исправленным фиктивным override. В текущем dependency graph это dev-инструменты;
публичный сервер не принимает пользовательские glob-шаблоны. Dev/test servers
не следует выставлять в интернет. После выпуска upstream fix нужно обновить
lockfile и повторить аудит/проверки.

Критические предупреждения старого Vitest устранены обновлением до 5.1.0.
Для `effect` и `deepmerge-ts` применены overrides на исправленные версии;
Prisma generate/migrations, формы, сборка и тесты после этого проверены.
Машинные отчёты: [audit-production.json](audit-production.json), [audit-all.json](audit-all.json).

## Что ещё требуется перед публичным запуском

1. **Настоящий HTTPS-домен и хостинг.** Сейчас используются localhost-настройки.
2. **CA Supabase и строгая проверка TLS.** Текущая demo-конфигурация шифрует
   соединение через `sslmode=require`, но отдельный строгий probe без доверенного
   CA завершился `self-signed certificate in chain`. Нельзя считать его проверкой
   подлинности сервера. Нужен CA из Dashboard и `sslaccept=strict`/`sslcert`;
   шаблон и runbook подготовлены. Непроверенный CA автоматически не доверялся.
3. **Реальные товары и данные магазина** — если планируются реальные продажи.
   Демо-данные не должны выдавать себя за настоящий ассортимент/наличие.
4. **Внешние сервисы:** Click/Payme, S3-бакет, SMS/рассылка и доставка не подключены.
   Онлайн-платёж не симулируется. S3-код проверен на авторизацию/валидацию,
   но не на настоящем бакете без credentials.
5. **Docker/CI и мониторинг на целевом хостинге.** Конфигурации подготовлены;
   Docker engine отсутствует, поэтому образ здесь не собирался. Standalone runtime
   проверен непосредственно. Lighthouse/полевые Core Web Vitals и Safari/Firefox
   отдельно не измерялись; браузерный прогон выполнен в Chromium.
